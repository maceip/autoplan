## FlashHandoff keynote (preso/)

- **Task**: build the 6-slide keynote described by
  `~/.gemini/antigravity/brain/33dcff35-.../flashhandoff_keynote_rubric.md`.
- **Blocker found**: `.key` cannot be written here. macOS denies Apple events to
  Keynote (`errAEEventNotPermitted -10004`) for every document-level command
  (`documents`, `make new document`, `save`); only static props like `version`
  resolve. Keynote is sandboxed and the host process has no Automation grant.
  `.key` is a zip of snappy-compressed IWA protobufs — not authorable by hand.
- **Shipped instead**: `preso/FlashHandoff.pptx` + `FlashHandoff_preview.pdf`,
  built from a shared layout spec so the PNG preview and the PPTX cannot drift.
- **Theme reconstructed from the original file**: fonts are
  `Halvar Breitschrift DEMO ExBold` (name ID 1, not "ExtraBold"),
  `IBM Plex Mono`, `Helvetica Neue`; palette black + yellow #EDEE05 /
  blue #2E9FE0 / green #33C42B / magenta #E840C8 / orange #F0741A.
  The 3D rib textures are procedural (`_build/texture.py`), not bitmaps —
  the .key only shipped 356x200 thumbnails.
- **Gotchas worth remembering**:
  - `python-pptx` `RGBColor` subclasses `str`; `str(c)` gives the hex.
  - `a:ln` child order is fill → prstDash → headEnd → tailEnd. Appending
    prstDash after tailEnd produces a file PowerPoint may reject.
  - Halvar Breitschrift DEMO lacks the em dash and arrow glyphs; keep `—`/`→`
    out of the display face (mono is fine).
  - Keynote rewrites an opened .key (metadata, stylesheet, previews) even when
    nothing is edited; opening a user's file is not read-only.
- **Build pipeline** lives in `preso/_build/`: `spec.py` (canvas/primitives),
  `slides.py` (content), `build_pptx.py`, `render.py` (spec→PNG),
  `verify.py` (pptx→PNG, renders the real file back).
  Rebuild: `python3 -c "import slides,build_pptx; build_pptx.build(slides.all_slides(),'FlashHandoff.pptx')"`.
- **Conversion**: `_build/pptx_to_key.applescript` converts once Automation
  permission is granted; otherwise File > Save As in Keynote.
